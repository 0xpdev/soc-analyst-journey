## 1. What is a SOC?

A Security Operations Center (SOC) is a centralised team responsible for monitoring an organisation's IT infrastructure, identifying suspicious activities, investigating security alerts and coordinating responses to potential threats.

A SOC operates continuously to help organisations detect and respond to cyber threats.

### Why does an organisation need a SOC?

- Detect potential security threats.
- Monitor systems and network activities.
- Investigate suspicious behaviour.
- Reduce the time attackers remain undetected.
- Minimise the impact of security incidents.

### Dwell Time

Dwell time refers to the amount of time an attacker remains undetected inside an organisation's network.

Reducing dwell time helps limit the potential damage caused by an attack.

## 2. SOC vs NOC vs Incident Response Team

| Team | Primary Responsibility |
|---|---|
| SOC | Monitors and investigates security threats. |
| NOC | Monitors network performance, availability and connectivity. |
| Incident Response (IR) | Handles confirmed security incidents, containment and investigation. |

### Simple Analogy

- SOC: Watch Tower
- NOC: Walls and Fences
- IR Team: Special Forces

---

## 3. Responsibilities of a SOC L1 Analyst

A Level 1 SOC Analyst is generally responsible for initial alert monitoring and investigation.

Key responsibilities:

- Monitor alerts generated by SIEM platforms.
- Analyse security logs.
- Identify suspicious IP addresses and user activities.
- Classify alerts as True Positive or False Positive.
- Document investigation findings.
- Escalate suspicious or confirmed incidents to higher-level analysts.

### Alert Triage Lifecycle

**Step 1: Alert Trigger**

A SIEM platform generates an alert when an activity matches a detection rule.

**Step 2: Log Analysis and Context**

The analyst examines relevant information, including:

- Source and destination IP addresses.
- Timestamps.
- User accounts.
- Windows Event Logs.
- Firewall and proxy logs.

**Step 3: Decision Making**

Determine whether the alert is:

- True Positive: The alert represents genuinely suspicious or malicious activity.
- False Positive: The alert was triggered by legitimate or harmless activity.

**Step 4: Action**

- False Positive: Close the alert with a clear explanation.
- True Positive: Document evidence and escalate to L2/L3 or the Incident Response team as appropriate.

## 4. Important SOC Technologies

| Technology | Purpose | Examples |
|---|---|---|
| SIEM | Collects and correlates security logs | Splunk, Microsoft Sentinel, IBM QRadar |
| EDR/XDR | Monitors endpoint activity and detects threats | CrowdStrike, SentinelOne, Microsoft Defender |
| Ticketing | Tracks investigations and incidents | Jira, ServiceNow |
| Threat Intelligence | Checks the reputation of suspicious indicators | VirusTotal |

### Understanding the difference

- SIEM: Helps analysts identify suspicious activity across collected logs.
- EDR/XDR: Provides endpoint visibility and response capabilities.
- Ticketing: Maintains investigation records.
- Threat Intelligence: Provides additional context about indicators such as IP addresses, domains and file hashes.

## 5. Common Attack Scenarios

### A. Phishing

**What happens?**

An attacker sends a deceptive email or message to trick a user into clicking a malicious link or sharing sensitive information.

**SOC investigation:**
- Inspect email headers.
- Check sender and domain reputation.
- Investigate suspicious URLs.
- Review endpoint activity if the user interacted with the email.

### B. Malware Execution

**What happens?**

Malicious software executes on a system to perform unauthorised activities.

**SOC investigation:**
- Review endpoint detection alerts.
- Examine suspicious processes.
- Check file hashes.
- Identify Indicators of Compromise (IOCs).
- Escalate for further analysis when necessary.

### C. Ransomware

**What happens?**

An attacker encrypts files and may demand payment to restore access.

**Possible indicators:**
- Unusual file encryption activity.
- Ransom notes.
- Deletion of backup or shadow copies.

**SOC response:**
- Urgently escalate.
- Coordinate isolation of affected systems with the response team.
- Document the incident timeline.

### D. Brute Force Attack

**What happens?**

An attacker repeatedly attempts different passwords to gain unauthorised access.

**Possible indicators:**
- Repeated failed login attempts.
- Account lockouts.
- Unusual source IP addresses.

**Important investigation concept:**

The frequency and context of failed login attempts matter. Fifty failed attempts in one minute can indicate automated activity, whereas fifty attempts spread across a day may have a different explanation.

## 6. Important SOC KPIs

| KPI | Meaning |
|---|---|
| MTTD | Mean Time to Detect |
| MTTR | Mean Time to Respond |

These metrics help organisations evaluate the effectiveness of their security monitoring and incident response processes.

---

## 7. Documentation in SOC

Every investigation should be documented properly in a ticketing platform.

A useful investigation record should contain:

- Alert description.
- Relevant timestamps.
- Source and destination information.
- Evidence collected.
- Investigation steps.
- Final classification.
- Recommended action or escalation.

**Key takeaway:** If an investigation is not documented, it becomes difficult to track, review or learn from it.
